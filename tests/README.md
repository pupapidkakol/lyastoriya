# Модульні тести ЛяСторії

Тести написані на вбудованому в Node.js тест-раннері (`node:test`). Ставити jest, mocha чи jsdom не потрібно.

## Що потрібно

- **Node.js 22.13 або новіший** (краще 24 LTS), бо сервер використовує вбудований `node:sqlite`.
- Для тестів сервера потрібні залежності сервера. Їх достатньо встановити один раз:

```powershell
cd server
npm install
cd ..
```

## Як запустити

З кореня репозиторію:

```powershell
node --test --test-force-exit "tests/*.test.js"
```

Один файл: `node --test tests/games.test.js`

Якщо `server/node_modules` немає, тести сервера **пропускаються** (skip) з підказкою, решта тестів працює.

## Що перевіряється

| Файл | Що тестує |
|---|---|
| `data.test.js` | JSON у `public/data`: структура, унікальні id, правильні відповіді існують, картинки є в `public/images`, посилання http(s), зв'язок запитань із теорією |
| `games.test.js` | Квіз, «Фейк чи факт», «Хронологічний виклик», «Знайди відповідність»: проходження гри, рахунок, тексти результату, збереження результату, обробка помилок |
| `timeline.test.js` | «Коли це сталося?»: формула балів, відмінки («1 рік / 2 роки / 5 років»), повзунок і кнопки ±, межі шкали |
| `game-page.test.js` | Сторінка гри: список ігор збігається із сервером, невідомий `?g=` не підвантажує скриптів |
| `server.test.js` | API: реєстрація, вхід, сесії, вихід, результати й статистика, CSRF/Origin, 415/400/404, ліміт спроб (429), захисні заголовки, статика |

## Як це влаштовано

- `helpers/browser-env.js` — маленький «браузер» для Node: фейковий DOM, `fetch` читає файли з `public/`, `api.saveResult` записує, що гра хотіла зберегти. Ігри запускаються **без змін у їхньому коді**.
- Тести сервера запускають справжній `server/server.js` на випадковому порту з **тимчасовою** базою в системній папці temp. Справжня `server/data/app.db` не змінюється.
